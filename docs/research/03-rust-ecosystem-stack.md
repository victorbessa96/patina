# Rust Ecosystem Survey: Substance-Painter-class DCC (2026-10-09)

**Headline:** The rendering, imaging, and foundation layers are production-grade (wgpu 30, naga 30, exr, half, glam, wasmtime). The two genuine chasms are (1) **stylus/tablet input** — winit only just grew `Pointer` pen events in the 0.31 betas, Wintab/X11 are unsupported, and every existing tablet crate is hobby-scale — and (2) **interchange/material standards** — zero real MaterialX bindings, OCIO bindings are one-author 0.2.x, USD is a pre-1.0 pure-Rust port. Both are budget-to-own items, not pick-a-crate items.

## Area notes (verified specifics)

1. **GPU.** wgpu 30.0.1 (2026-08-22). Bindless: `binding_array` since v24/v25 — DX12 `PARTIALLY_BOUND_BINDING_ARRAY` on Resource Binding Tier 3 (most D3D12 hw), Metal significantly improved in v25, storage-buffer arrays added v30. Still feature-gated, not "always on." Ray tracing: `EXPERIMENTAL_RAY_QUERY` (accel structs merged in, v27), wgsl-in RT pipelines v29, spirv-out v30, DXR in HAL since v24 — all flagged experimental/breaking. **Timeline semaphores: not exposed** (v30 added only `vulkan::Queue::add_wait_semaphore` for external-interop via `VK_KHR_external_semaphore*`). Mesh shaders experimental (v28). HDR surface config landed v30: `SurfaceColorSpace::{Bt2100Pq, Bt2100Hlg, ExtendedDisplayP3}`, `Surface::display_hdr_info` (DX12/Metal ✅, Vulkan driver-dependent). naga 30.0.1 is at full lockstep; naga_oil 0.23.0's own Cargo.toml pins naga=30/wgpu=30. ash 0.38.0+1.3.281 — latest crates.io release 2024-04-01 (repo pushed 2026-10-06): release cadence stalled ~2.5y; fine as wgpu's internal backend, poor as primary API. **Recommendation: wgpu, with a thin `as_hal` escape hatch reserved for Vulkan-only needs (timeline semaphores, external memory).** Don't architect on RT/mesh shaders.
2. **Windowing/stylus.** winit 0.30.13 stable / 0.31.0-beta.3: pointer overhaul added `PointerMoved/PointerButton` with `PointerKind::Pen` on **Windows, Wayland, Web**; Apple Pencil on iOS; beta.3 fixed X11 dropping absolute pointing devices without pressure axes. X11 pen proper: still missing (community PRs #2647/#2396/#1879 unmerged). Wintab: unsupported by winit, period. Windows reality: modern screen-digitizer tablets = Windows Ink (WM_POINTER, pressure capped 1024 levels, hover-button gaps); external Wacom/Huion tablets commonly configured for Wintab — pro apps need **both**, switchable at runtime (Drawpile's docs/issues confirm dual-path is table stakes). Linux: Wayland `zwp_tablet_unstable_v2` (compositor conformance hit-or-miss); X11 via XI2 valuator axes (range info missing). Crate inventory: **octotablet 0.1.0** (2024-03; repo last pushed 2025-11; Wayland v2 + Windows Ink RealTimeStylus "Complete"; pads not exposed on Windows; X11 "I'll try"; 40 stars) — the best abstraction but dormant-ish; **wintab_lite 1.0.1** (libloading-based, minimal, works, by author's own account "lightly oxidized"); **efude-input 0.1.0** (2026-09-26, from a Rust painting app, 15 downloads — signal the niche is being scratched, nothing proven); easytab 0.3.0 (EasyTab port, 59 dl); `input` (libinput) 0.10.0, hidapi 2.6.7, x11rb 0.14.0, smithay-client-toolkit 0.21.1 for the DIY path. **Recommendation: build an in-house `stylus` crate with a poll-based event queue (Wintab32 polling works fine under winit — only needs the HWND), fork/absorb octotablet, and upstream improvements. This is a must-own layer.**
3. **UI.** egui 0.36.2 (very active, 25.6M dl, MIT/Apache); egui-wgpu 0.36.2 is first-class; egui_dock 0.21.1 tracks egui 0.36 (tab splits, serialization, 641 stars). Caveats: no stylus/pressure in egui's input model (issue #2104 open since 2022 — pressure only reachable by intercepting raw winit events before eframe consumes them, confirmed working by users in that thread), accessibility still maturing, immediate-mode text is not DTP-grade (pair with parley/cosmic-text for rich text). GPUI: crates.io 0.2.2 is pre-1.0 macOS/Linux-only; upstream Zed monorepo added Windows (Win32+DirectWrite) and gpui-standalone distributions exist (gpui-standalone 1.4.4 crates / 1.6.3 git), but it's Zed-shaped, doc-thin, breaks often, and does **not** use wgpu. gpui-component 0.7.1 (16.6k stars) delivers a genuinely pro dock workspace (DockArea, tiles, persistent layout) — the strongest "Painter chrome" available in Rust today, at the cost of GPUI's volatility. Iced 0.14: solid, Elm-ish, no docking, weaker for a custom 3D-canvas-centric layout. Slint 1.18.1: most mature toolkit but triple-licensed GPLv3/royalty-free-with-attribution/commercial — permanent licensing decision for an OSS project, plus DSL/canvas integration friction. **Recommendation: egui + egui_dock — wgpu synergy, permissive license, docking exists, and the canvas (the hard part) is your own wgpu layer anyway. Route pen events straight from winit into your canvas, bypassing egui input.**
4. **Mesh/scene.** glTF: gltf 1.4.1 (solid, slow-moving) + meshopt 0.6.2. FBX: **ufbx 0.11.5** official bindings, upstream C lib (1414 stars, pushed 2026-10-01, MIT, used in production engines) — the only credible route; Autodesk FBX SDK is proprietary with redistribution constraints (fbxsdk-sys 0.1.0, dead since 2019 — don't). fbxcel 0.9 abandoned 2022. USD: **openusd 0.7.0** pure-Rust (usda/usdc/usdz R/W, LIVRPS composition, Stage API, event-driven diffs; active weekly; explicit "no API stability until 1.0") + openusd-schemas (UsdGeom/UsdShade/UsdSkel). pxr 0.2.0 targets USD 22.11 with 50-minute vendored builds; rust-usd 0.0.5 is a fresh pxr FFI. For a painter, scope USD to import + primvar/texture-set export; golden-test against pxr. Half-edge: nothing above hobby scale (halfedge 0.3.0 = 293 dl; smesh 0.2.7; hedge 0.2.1 from 2019; meshx 0.7.0) — **own it**; a painter's topology needs (per-paint-layer masks, UV seam awareness) are bespoke anyway. Subdivision: opensubdiv-rs 0.5.0 (2026-10-02, "faithful Rust port", 224 dl, unproven) vs OpenSubdiv C++ (Pixar, active, GPU kernels heavy). **Recommendation: CPU adaptive Catmull-Clark in-house or a hard-verified opensubdiv-rs; keep the OSD C++ FFI option for GPU adaptive refinement later.**
5. **Images.** image 0.25.10 (208M dl) for standard formats (u16 + f32 paths); **exr 1.74.2** pure-Rust OpenEXR is excellent (77.8M dl via transitive use); **half 2.7.1** for f16/bf16 storage; ktx2 0.5.0 + ddsfile 0.6.0 for containers; compression via **ctt 0.6.0** (vendored bc7enc_rdo + ISPC bc7e + Compressonator + astcenc behind one API — new but authored by a wgpu maintainer) or intel-tex-2 0.5.0; rusty_dds 0.9.0 for DDS tooling. Skip the stale openexr/openexr-sys (2021).
6. **Color.** **ocio-rs 0.2.1** (2026-07-15): bindings to OCIO v2.5.2 with bundled builds, CPU/GPU processors, and GPU shader extraction (exactly what a viewport display pipeline needs); coverage "broad," hardening in progress — single-maintainer risk. Pure-Rust `ocio` port 0.1.0 published 2026-10-04, 242 dl — too early. lcms2 6.2.0 (7.2M dl) for ICC profile read/write on asset export. HDR display output rides wgpu 30's SurfaceColorSpace/display_hdr_info. **Recommendation: ocio-rs with vendored OCIO, plus contract tests against reference transforms.**
7. **Materials.** MaterialX Rust bindings are 0.0.0 placeholders (crates.io/crates/materialx, 2021). The .mtlx format is XML with a modest node-graph schema — a subset parser (quick-xml 0.42.0) covering UsdPreviewSurface + OpenPBR node graphs is 2–4 weeks of work; full document model or C++ interop via autocxx 0.30.0 is the heavy alternative. OpenPBR: ASWF subproject of MaterialX, spec published (DigiPro 2025 paper), reference implementation is a single über-shader in MaterialX — **you implement it once in WGSL** (~the Autodesk Standard Surface lineage); `openpbr` crate 0.1.0 (2026-09-29) gives typed parameter defaults/ranges. **Recommendation: own .mtlx subset parsing + WGSL OpenPBR; skip MaterialX C++ until interoperability demands it.**
8. **Plugin runtime.** wasmtime 49.0.2 stable (50.0.0-rc.1 in flight); **WASI 0.3 ratified 2026-06-11** with native async components; Wasmtime 46+ ships it by default; wit-bindgen 0.62.0 current. Component model is the right sandbox for user plugins (exporters, filter/generator ops, brush parameter graphs) — **but not the inner paint loop**; define a host-provided stamp/composition API so plugins orchestrate rather than execute per-pixel hot paths. Native route: libloading 0.9.0 is fine, abi_stable 0.11.3 untouched since 2023 — avoid committing to Rust-to-Rust dynlib ABI now. hot-lib-reloader 0.8.2 for internal dev loops. extism 1.30.0 if you want multi-language PDKs out of the box.
9. **Foundations.** glam 0.34.1 (SIMD, 157M dl); rayon/parking_lot/dashmap/crossbeam all current and boringly reliable. **tokio not needed in core** — a DCC is thread-pool + channel shaped; keep async out of the paint path (GPU sync points and async runtimes mix badly). Undo: roll your own memory-budgeted command journal (undo 0.52 as API reference; System76's cosmic_undo_2 is a proven alternative). Profiling: tracy-client 0.19 + profiling facade, puffin 0.20 as option. Errors: thiserror 2.0.21 + anyhow 1.0.104 + miette 7.6.0 for asset-loading diagnostics. notify 8.2.0 for hot-reload watching.
10. **Distribution.** cargo-dist 0.32.0 (repo active Sep 2026) generates the full GitHub Actions release pipeline (MSI via WiX, shell installers, Homebrew, GH Releases) from a tag; cargo-packager 0.11.8 gives NSIS + AppImage; cargo-wix 0.3.9 for hand-rolled MSI; cargo-bundle 0.12 has a spotty history — skip. Linux: ship a Flatpak (best driver-sandbox story for Vulkan) + AppImage tarball-alternative. CI on GH Actions: windows-latest + ubuntu matrix; wgpu's own CI pattern (Vulkan lavapipe/llvmpipe for headless GPU tests) works for automated render tests; add pen-input simulation tests once the input layer exists.

## (b) Top-10 risks and mitigations

1. **Stylus input is the weakest layer in Rust** (winit X11 pen missing, Wintab unsupported, octotablet dormant, all crates <5k downloads). *Mitigation:* budget a owned `stylus` crate from day one; dual Windows backend (Ink WM_POINTER + Wintab32 polling via HWND); Wayland zwp_tablet_v2 + X11 XI2 on Linux; absorb/fork octotablet; hardware test matrix (Wacom/Huion/XP-Pen); upstream to winit.
2. **winit 0.31 is in beta and just changed the pointer event model** (pressure regressed mid-0.30→0.31 per issue #99). *Mitigation:* pin 0.30.13 until 0.31 final; wrap winit events behind your own enum; CI against 0.31 betas.
3. **wgpu experimental surface churn** (RT pipelines, mesh shaders, bindless rules changed v24→v30). *Mitigation:* core painting uses only stable wgpu; experimental flags behind cargo features; keep a thin HAL abstraction so `as_hal` Vulkan fallbacks are cheap.
4. **No timeline semaphores / manual heap control in wgpu** — limits multi-queue sync and sparse-residency-style texture streaming designs. *Mitigation:* design tile-virtualization on storage-buffer arrays + per-tile bind groups; use `vulkan::Queue::add_wait_semaphore` interop for external sync; go ash only if wgpu demonstrably blocks (measure first).
5. **naga_oil lockstep** — every wgpu major requires a coordinated naga_oil release (it's at 0.23 for wgpu 30). *Mitigation:* version-pin wgpu+naga+naga_oil together in one workspace update; vendor naga_oil locally if it lags.
6. **ocio-rs is single-maintainer 0.2.x.** *Mitigation:* vendored OCIO build via ocio-sys; golden tests vs OCIO C++ CLI; the GPU-shader-extraction path can be replaced with baked LUTs if bindings rot.
7. **USD fidelity: pure-Rust openusd vs pxr semantics** (pre-1.0, no stability guarantees). *Mitigation:* scope to UsdGeomMesh/UsdShade/UsdUVTexture + primvars; golden-file round-trips vs usdview; keep rust-usd (pxr FFI) as escape hatch.
8. **MaterialX has zero bindings** — .mtlx import/export is unserved. *Mitigation:* own subset parser + OpenPBR WGSL per reference mtlx; conformance-test against MaterialX's reference renders; track MaterialX 1.39.
9. **egui ceiling for pro UI** (pressure absent from input model, accessibility, dense-table UX). *Mitigation:* pen events bypass egui into canvas directly (proven workaround in issue #2104); keep panels behind trait boundaries so a GPUI migration stays possible; contribute the egui `Pen` event patch upstream (small, high-leverage).
10. **Packaging/driver matrix hell** (Vulkan driver variance on Linux, MSVC redistributables, Flatpak GPU permissions). *Mitigation:* crash reporting + GPU allowlist; lavapipe software-Vulkan fallback path; smoke tests on clean Win10/11 + GNOME/KDE VMs in Actions; Flatpak as the supported Linux story.

## (c) The three hardest technical bets

1. **Owning the stylus stack.** There is no crate to pick that makes this work; there is a fork to build. Windows needs both Wintab (vendor tablets, hover buttons, >1024 pressure) and Windows Ink (screen digitizers), Linux needs Wayland-tablet-v2 plus X11 XInput — under winit, which itself only covers part of it and just reworked its event model. This is core-product differentiating tech (Krita/Photoshop-class feel: event-rate-independent stamp spacing, pressure smoothing, proximity handling) and the bet is that a small team can build and maintain the platform layer faster than upstream winit converges. Evidence it's scratchable: wintab_lite + octotablet + efude-input collectively prove all the API paths exist in Rust; nobody has integrated them into a production loop.
2. **Painter-class texture streaming on wgpu's abstraction.** Substance-class painting means virtualized 4K–8K texture sets, many channels/materials per object, and a syncing story between paint compute and viewport sampling — with no timeline semaphores, partially-bound descriptor arrays, and a bindless model that differs per backend. The bet: a tile/paging design built purely on stable wgpu primitives (storage-buffer binding arrays, per-draw rebinds) suffices at interactive rates, with the Vulkan `as_hal` hatch as insurance. This is the main performance bet of the project.
3. **Standing up the interchange/material layer solo.** MaterialX (no bindings), OpenPBR (own WGSL implementation from spec), OCIO (0.2.x bindings), USD (pre-1.0 pure-Rust). Every neighboring DCC ecosystem solved this with C++ libraries; Rust forces the choice between thin FFI (autocxx/bindgen build complexity, OCIO-class C++ deps in CI on Windows) and pure-Rust reimplementation (fidelity risk, sustained maintenance). The bet: the pure-Rust subset route — .mtlx parser + OpenPBR shader + ocio-rs + openusd — covers 90% of real asset traffic (games/USD pipelines) and stays debuggable; the mitigation is golden-file conformance against the C++ reference tools on every commit.

## Net recommendation

wgpu 30 + naga/naga_oil + winit 0.31 + egui/egui_dock + glam/rayon foundations + exr/image/half/ktx2/ctt imaging + ocio-rs + ufbx/gltf/openusd import + wasmtime component-model plugins + cargo-dist/Flatpak distribution — and treat stylus input, texture virtualization, and the MaterialX/OpenPBR layer as first-class internal engineering bets, not dependencies.
