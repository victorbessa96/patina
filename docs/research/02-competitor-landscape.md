# Competitive Landscape: Open-Source Substance Painter Alternative in Rust (as of 2026-10-09)

**Premise correction first:** ArmorPaint is **not Rust-based**. It began as Haxe compiled to JS running on V8, and its 1.0 release (Sept 2026) is a full **C rewrite** with zero external libraries — the "closest living relative" framing holds, but the implementation language is C, not Rust. Sources: [forums.armorpaint.org/t/improved-performance/118](https://forums.armorpaint.org/t/improved-performance/118), [armory3d/armorpaint](https://github.com/armory3d/armorpaint) (GitHub language stats: C ≈10.2MB of code).

## 1. ArmorPaint — DEEP DIVE

### Architecture
- **Lineage:** Built by Lubos Lenco (Armory3D team) on Kore/Kha (hardware abstraction) + Kongruent (shader cross-compiler) by RobDangerous; originally Haxe + V8 JS engine, first released 2018. v1.0 (tagged 2026-09-03) is a complete C rewrite: no external libs, no GC, monolithic repo, 2.8MB compressed binary ("fits on two 1.44MB floppies"), single-file portable build via clang C23 `#embed`, and even bundles tcc so you can self-compile. [forums.armorpaint.org/t/improved-performance/118](https://forums.armorpaint.org/t/improved-performance/118), [3dxdev.com](https://3dxdev.com/armorpaint-1-0-is-out-rewritten-in-c-and-a-third-the-size/), [git.armorpaint.org](https://git.armorpaint.org/)
- **The 'iron' engine:** The old engine was `armory3d/iron` ("3D Engine Core… built with Kha and Haxe", now archived). In 1.0 it became **armorcore** ("Kinc + V8", archived and folded into the monorepo as `base/`): `base/sources/iron_gpu.h` is a thin GPU abstraction layer that dispatches to `backends/direct3d12_gpu.h` / `metal_gpu.h` / `webgpu_gpu.h` / `vulkan_gpu.h`. [github.com/armory3d/iron](https://github.com/armory3d/iron), [github.com/armory3d/armorcore](https://github.com/armory3d/armorcore), [iron_gpu.h](https://github.com/armory3d/armorpaint/blob/75f7eaeb/base/sources/iron_gpu.h), [git.armorpaint.org/tree/base](https://git.armorpaint.org/tree/base) ("3D engine targeting Direct3D12, Vulkan, Metal and WebGPU. Based on Kore.")
- **GPU backends:** D3D12 (Windows), Vulkan (Linux/Android), Metal (macOS/iOS), WebGPU (WASM); hardware ray tracing on D3D12, Vulkan, Metal. [iron_gpu.h](https://github.com/armory3d/armorpaint/blob/75f7eaeb/base/sources/iron_gpu.h), [CG Channel](https://www.cgchannel.com/2026/09/armorpaint-1-0-is-out-after-eight-years-in-early-access/)
- **UI layer:** Custom immediate-mode UI (ZUI heritage from Armory — [github.com/armory3d/zui](https://github.com/armory3d/zui), "Immediate Mode User Interface"). Through 0.9 the app logic was JS-on-V8 (Krom); **1.0 moved scripting to C** — plugins import as `.c` or `.zip` ([manual](https://armorpaint.org/manual)), powered by a homegrown mini-C interpreter (`paint/sources/minic_api.c`, `minic_impl.c` in the repo; script tab gained autocomplete/minimap; `--api`/`--script` CLI args). Old JS plugin docs survive at [deprecated-armory3d/armorpaint_docs](https://github.com/deprecated-armory3d/armorpaint_docs) (`.js`/`.wasm` imports — that's the "JS-based UI layer" era).
- **Paint stroke architecture:** Painting "runs completely on the GPU"; a brush stroke is **a GPU pass over the texture, not a CPU blit** ([gianlucascattarella.it analysis](https://www.gianlucascattarella.it/blog/armorpaint-1-0-eight-years-six-build-targets/)). Brushes are **node graphs** evaluated per stroke ([manual#brushes](https://armorpaint.org/manual)); brush materials are Cycles-like node graphs ([manual#materials](https://armorpaint.org/manual)). Layers are per-object with per-layer resolution/color depth, masks, groups, fill/path/curve/decal/text layers, 2D view. 4K painting on Intel HD4000 minimum, 16K on RTX 2080+; BC7 compression cut VRAM for 1.0 (7M-tri/800MB .obj benchmark on the forum post).
- **Baking:** Not a separate dialog — a `Bake Texture` **material node**. Ray-traced modes (AO, Thickness, Bent Normal, Lightmap) accumulate samples via **Brute Pathtracer**, a custom "trades correctness for speed" RT engine (64 objects / 1024 instances; fast & quality modes) — [brute_pathtracer.md](https://github.com/armory3d/armorpaint/blob/75f7eaeb/base/docs/brute_pathtracer.md), [manual#baking](https://armorpaint.org/manual). Non-RT modes: curvature, normal/object normal, height, derivative, position, texcoord, material/object ID, vertex color. 1.0 changelog: "Improved raytraced baking," "Moved bake tool to 'bake texture' material node." [forums.armorpaint.org/t/release-1-0/84](https://forums.armorpaint.org/t/release-1-0/84)

### License, pricing, community
- **License:** zlib/libpng — [license.md](https://github.com/armory3d/armorpaint/blob/main/license.md). Permissive; GPL-compatible; free to compile; sell binaries.
- **Pricing:** $19 one-time on itch.io (all updates free), iOS $17.99, Android $19.99; funded by binary sales + a $25k Epic MegaGrant (2020). [armorpaint.org/download.html](https://armorpaint.org/download.html), [CG Channel MegaGrant](https://www.cgchannel.com/2020/02/armorpaint-wins-25000-epic-megagrant/)
- **Community:** GitHub 5,338★ / 612 forks / 32 contributors — but **luboslenco has 6,172 commits vs 140 for the #2 contributor** (GitHub API, 2026-10-09). Discourse forum at forums.armorpaint.org (launched ~Feb 2026), plus YouTube/ArtStation/X. Cadence: 0.8 (Oct 2021) → 0.9 (Sept 2023) → 1.0 (Sept 2026).

### Concrete gaps vs Substance Painter
- No `.sbsar` runtime ecosystem / material library; smart-material and mask ecosystem is thin ([Scattarella](https://www.gianlucascattarella.it/blog/armorpaint-1-0-eight-years-six-build-targets/): "the gap lives in the ecosystem rather than the brush engine").
- **No stroke stabilization** ([forum troubleshooting post](https://forums.armorpaint.org/t/troubleshooting-problems-solutions-version-1-0/122)); UDIM seam painting issues ([forum](https://forums.armorpaint.org/t/paint-across-udims/120)); camera/unit-scale irritations ([HN thread](https://news.ycombinator.com/item?id=35507558)); "a little simplistic for many goals" ([polycount](https://polycount.com/discussion/234542/anyone-tried-armor-paint-any-good)). Basic-only sculpting/UV editor (1.0's own framing: "basic"). Live-link plugins not yet at 1.0.

### What to copy / avoid
- **Copy:** GPU-resident painting loop (enables 16K on consumer GPUs); stroke-as-GPU-pass; bake integrated as a node; zlib + paid-binaries funding; sub-10MB portable no-install distribution; custom-engine control over memory (BC7, 2.9s debug builds).
- **Avoid:** Single-maintainer bus factor (6,172 vs 140 commits — one person carries the entire 3-backend porting matrix, hence 2–3 years per point release, per [Scattarella](https://www.gianlucascattarella.it/blog/armorpaint-1-0-eight-years-six-build-targets/)); building three GPU abstraction layers from scratch when Rust has wgpu (one SPIR-V→native layer covers D3D12/Vulkan/Metal/WebGPU); "basic" everything-adjacent features (sculpt, UV editor) diluting the core; JS→C migration pain — choose the scripting story up front.

## 2. Blender Texture Paint + Baking (2026 state)
- **Capability:** Texture Paint is projection-based painting in 3D viewport + Image Editor; brush types: draw, soften (blur/sharpen), smudge, clone, fill, mask ([manual](https://docs.blender.org/manual/en/latest/sculpt_paint/texture_paint/brushes.html)). 4.3 introduced the brush-asset system (100+ brushes, Essentials library) ([4.3 release notes](https://developer.blender.org/docs/release_notes/4.3/sculpt/)); 5.0 added pixel-art brushes, pen-pressure curves, scene-linear brush colors ([5.0 release notes](https://developer.blender.org/docs/release_notes/5.0/sculpt/), [blender.org/5-0](https://www.blender.org/download/releases/5-0/)). Multires baking greatly improved in 5.0 (vector displacement, n-gons, bake-selected) ([blender.org](https://www.blender.org/download/releases/5-0/)).
- **Where a dedicated tool still wins:** Documented limitations — overlapping UVs unsupported, faces behind view unpaintable ([manual](https://docs.blender.org/manual/en/latest/sculpt_paint/texture_paint/introduction.html#known-limitations)); painting lags on 2K–4K with heavy meshes ([blenderartists 2022](https://blenderartists.org/t/painting-using-add-ons-vs-armorpaint/1403752), historic tracker perf bugs [#90825](https://projects.blender.org/blender/blender/issues/90825), [T51133](https://archive.blender.org/developer/maniphest/0051/0051133/index.html)); PBVH image-paint re-architecture was proposed exactly to reach "16K textures, 3D rather than just projection painting" ([T96223](https://archive.blender.org/developer/maniphest/0096/0096223/index.html)) but remains incomplete. Cycles baking ≠ game-art baking: community guidance is blunt — "Marmoset yields the best bakes… stay away from most bakers integrated in modeling software, Blender being a good example" ([3D Artist Handbook](https://sidney-eliot.github.io/3d-artists-handbook/texturing/baking)). No smart materials/masks, no fill-layer PBR stack, no padding/dilation control, no game-export presets.
- **Geometry Nodes' role:** procedural geometry/detail upstream of texturing, but its Bake node saves **intermediate geometry**, not texture maps ([manual](https://docs.blender.org/manual/en/latest/modeling/geometry_nodes/baking.html)); baking a GN-displaced mesh to a texture requires applying the modifier first ([blender.stackexchange](https://blender.stackexchange.com/questions/281386/)). GN is a complement, not a texture painter.

**Lesson:** Blender owns "free and good enough for base coats"; the defensible niche is performance (GPU-resident paint loop), game-art bakers, and PBR layer/mask ergonomics — exactly what Blender structurally lacks.

## 3. 3DCoat (Pilgway)
- Sculpting (voxel) + market-leading auto-retopo (AUTOPO) + painting bundle, Windows/Linux/macOS. 2026 release added a **GPU node-based texturing system** (own NGL GLSL-based node language, separate GPU/CPU executables), 30 PBR channels, new-gen Smart Materials/masks. [CG Channel](https://www.cgchannel.com/2026/07/pilgway-releases-3dcoat-2026-and-3dcoattextura-2026/), [3dcoat.com](https://3dcoat.com/news/article/3dcoat-2026-officially-released/), [Wikipedia](https://en.wikipedia.org/wiki/3D-Coat)
- **Does well:** retopo+paint+sculpt in one license; perpetual licensing with 12mo updates (individual €379, Textura texturing-only edition €159, rent-to-own 11×€41.60). [pilgway.com](https://pilgway.com/products/product-buy/3dcoattextura), [3dcoat.com/buy](https://3dcoat.com/buy/)
- **Weakness:** idiosyncratic "rooms" UI, smaller ecosystem than Adobe; the node system is new and still shipping CPU/GUI parity work. **Lesson:** the painting+retopo bundle is a real differentiator, and a cheap perpetual "texturing edition" (Textura) is a proven SKU split.

## 4. Marmoset Toolbag
- Baker/viewer gold standard for game art: bake groups isolate intersections, cage with **paintable offset & skew**, real-time rebake feedback, handles 50–100M-poly highs without crashing, low-to-low baking (5.02), cage-distance limiting + curvature fixes near UV seams (5.03), layer caching, Text/Scatter layers, UDIM fill layers. [marmoset.co/toolbag](https://marmoset.co/toolbag), [docs: projection tools](https://docs.marmoset.co/docs/projection-tools/), [docs: cage](https://docs.marmoset.co/docs/cage/), [5.03 release](https://marmoset.co/posts/marmoset-toolbag-5-03-available-now/), [CG Channel](https://www.cgchannel.com/2026/08/marmoset-releases-toolbag-5-03), [Handbook](https://sidney-eliot.github.io/3d-artists-handbook/texturing/baking)
- Pricing: $399 individual perpetual / $18.99/mo; studio $1,299 / $49.99/seat/mo. [marmoset.co/shop](https://marmoset.co/shop/tb5-individual-perpetual)
- **Why gold standard:** the bake→paint→render→ArtStation Viewer loop is closed in one tool with per-bake-group interactive error correction. **Critical note:** Toolbag is **Windows+macOS only — no Linux** — leaving the exact gap this project targets. ([CG Channel 5.03 sys reqs](https://www.cgchannel.com/2026/08/marmoset-releases-toolbag-5-03))
- **Lesson:** bake quality is a moat built from a thousand correction UX details (skew painting, per-group cages, dither, Mikk/xNormal tangent space) — budget for baker polish, not just breadth.

## 5. Mari (Foundry)
- Born at Weta for *Avatar* (2.5M textures, 54 painters, 20M+ poly assets, 30GB/channel). [Foundry case study](https://www.foundry.com/insights/film-tv/mari-avatar), [wetafx.co.nz](https://www.wetafx.co.nz/research-and-tech/technology/mari)
- **Architecture:** projection-based **paint buffer** ("pane of glass"; paint 2D → bake to surface with B; AutoBakeAndClear/ClearOnly/Manual) ([docs](https://learn.foundry.com/mari/Content/user_guide/painting/paint_buffer.html)); thousands of UDIMs, 32K@32bit per tile ([foundry.com/products/mari](https://www.foundry.com/products/mari)); Multi-Paint (8 streams from one node) in 7.5, co-developed with Wētā FX ([Foundry news](https://www.foundry.com/news-and-awards/foundry-introduces-multi-paint-support-mari-75)); in-app Bakery; Qt5/PySide2 Python pipeline.
- **Cost:** individual $689/yr (promo $299/yr listed) or $86/mo; studio $1,289/yr, €3,139 full commercial; going **subscription-only Jan 2027**. [foundry.com/mari/subscription](https://www.foundry.com/products/mari/subscription), [foundry.com/products/mari](https://www.foundry.com/products/mari), [digitalproduction.com](https://digitalproduction.com/2026/01/19/foundry-locks-in-full-subscription-future-for-2027)
- **Why so expensive:** film-scale asset handling (the only tool that paints 20M-poly, tens-of-GB texture sets), studio pipeline integration, and a captive high-end market. **Lesson:** paint-buffer + UDIM streaming is the only proven architecture past ~100 UDIMs; also — every incumbent is fleeing perpetual licenses, which is the OSS pitch.

## 6. Quixel Mixer — autopsy
- Free material-blending tool (2018) built as a Megascans companion; 3D painting added 2020. Epic acquired Quixel Nov 2019 ([unrealengine.com](https://www.unrealengine.com/blog/epic-games-and-quixel-join-forces-to-empower-creators)); development effectively stopped with 2022.1 ("one of the final updates" — [CG Channel](https://www.cgchannel.com/2022/11/quixel-ships-mixer-2022-1/)); Megascans moved to Fab marketplace (Oct 2024); final offline build 2023.1 released Feb 2026 — no updates, no support, online features removed. [CG Channel autopsy](https://www.cgchannel.com/2026/02/quixel-mixer-has-been-discontinued-get-the-final-version-for-free/), [quixel.com](https://quixel.com/news/offline-version-of-quixel-mixer-now-available), [Fab transition FAQ](https://forums.unrealengine.com/t/quixel-to-fab-transition-faqs/2033839)
- **Cause of death:** strategic redundancy (Epic wanted the *library*, not the *tool* — Mixer's purpose was a Megascans funnel that Fab replaced), zero direct revenue (free product), parent cost-cutting (830 layoffs Sept 2023, another ~1,000 Mar 2026 — [Epic](https://www.epicgames.com/site/en-US/news/layoffs-at-epic), [The Verge](https://www.theverge.com/2023/9/28/23894266/epic-games-layoffs-fortnite-unreal-engine), [CG Channel](https://www.cgchannel.com/2026/03/epic-games-lays-off-another-1000-staff)).
- **Lesson:** a free tool whose only value is access to a proprietary library dies with the library's business model. An OSS painter must own its file formats and content on disk.

**Cause-of-death pattern:** full-DCC scope + GPU expertise required + single maintainer + no funding + "Blender/ArmorPaint already exists" gravity. Survival requires: narrow scope, engine-on-GPU from day one, funding, and >1 maintainer.

## Key takeaways for the Rust build
- **Correct the brief:** ArmorPaint is C (ex-Haxe/JS-V8), not Rust — but it *is* the architectural template: GPU-resident paint loop, stroke-as-pass, bake-as-node, zlib license, $19 paid binaries.
- **Differentiate where incumbents are weak:** Linux-native (Marmoset absent, Mari/Mudbox dying/dead, SP subscription-only at $59.99/mo indie — [Adobe](https://blog.adobe.com/en/publish/2025/02/20/substance-3d-innovations-pricing-updates)); UDIM + paint-buffer style streaming; game-art baker polish (the Marmoset moat); bus-factor-proof governance (ArmorPaint's one-dev model is its biggest exploitable weakness).
- **Name it Umber.**
